# VC-memory（投资记忆）

> 源码：https://github.com/AllenX95/VC-memory

## 一句话介绍

把项目判断写成一页决策记录、把行业判断拆成一条条可修正的观点，放进一个可同步的 Markdown 文件夹；侧边栏面板负责浏览、编辑与复盘，助手在对话里自动读取和更新，插件再定期把变化写成简报和变更日志。

> **实现状态（2026-10-18）**：项目条目、行业两级观点板（主题板 + 细分赛道板 + 观点操作）、简报、变更日志已实现；重启 Harness 后生效。旧格式的扁平行业条目仍可读取，会在行业树底部标为「待迁移」。

## 它是什么

- **项目 = 决策记录**：`项目/<公司>.md`，六小节（判断、依据、关键假设、风险与反证、证据时间线、复盘记录），带 verdict / 置信度 / 复盘周期。
- **行业 = 两级观点板**：`行业/<主题>/_主题.md` 是主题板（范围 + 跨赛道观点 + 下级索引），`行业/<主题>/<细分赛道>.md` 是细分赛道观点板；每条观点以「时间戳 + 当前结论」呈现，状态为 有效 / 待验证 / 被削弱 / 已证伪；修正时原地更新，旧→新摘要进 `日志.md`。
- **三个入口**：Web 面板、对话工具 `vc_memory`、自动注入的系统提示词段落——手动记、对话里问、模型自己想起来，都行。
- **复盘时钟（仅项目）**：项目条目带 `last_reviewed` / `next_review` / `review_cycle_days`；到期的项目在面板高亮并出现在提示词里。行业观点不设下次复盘日期，靠事件驱动修正。
- **定期简报**：按配置把项目变化与行业观点变化写成 `简报/<period>.md`。
- **变更日志**：每次新建/更新/复盘/生成简报/手动同步/导入示例，都会在 vault 根目录的 `日志.md` 追加一行概要，方便回看"什么时候改了什么"。
- **同步交给文件夹**：OneDrive / iCloud / Dropbox 或 Git；插件不建数据库、不藏状态，换台机器指向同一个文件夹即可。

## 安装与启用

本插件以 bundle 形式装进当前 Harness profile（桌面端），通过 Harness 的插件管理器完成安装与启用；它没有独立服务、没有额外端口——Host 半部挂在现有 Web 服务器上（同源 `/vc-memory/api`），面板是侧边栏里的一个入口。

- 在 Harness 侧边栏的 **插件** 面板（插件管理器）中确认 `@local/vc-memory` 已安装并启用。
- 侧边栏出现 **投资记忆** 图标即安装成功；插件首次加载会自动创建 vault 目录和其中的 `README.md`。
- 面板没出现时先重启 Harness 再看；不要另外启动插件进程。

## 数据在哪里

位置由配置 `vaultDir` 决定：

1. **默认（`vaultDir` 为空）**：系统里有 OneDrive 时用 `<OneDrive>\VC-Memory`，否则用 `<用户目录>\Documents\VC-Memory`；本机形如 `C:\Users\<你>\OneDrive\VC-Memory`。
2. **自定义**：把 `vaultDir` 写成某个同步文件夹的绝对路径，多台设备指向同一个逻辑目录即可。
3. **面板里改**：点右上角「设置」→「知识库位置」，可直接选择/输入绝对路径并保存（无需改 profile）；「恢复默认」会回到自动解析的位置。切换只改变插件指向，不移动、不删除旧文件。

目录结构：

```
VC-Memory/
├── README.md              # 首次运行写入的库说明
├── 日志.md                 # 变更日志：每次写入追加一行概要
├── 项目/                   # 每个项目一篇决策记录
│   └── xinghu-intelligence.md
├── 行业/                   # 两级观点板
│   └── 机器人/
│       ├── _主题.md        # 主题板：范围 + 跨赛道观点 + 下级索引
│       ├── 仓储机器人.md    # 细分赛道观点板
│       └── 人形机器人.md
└── 简报/                   # 插件按周期写出的简报
    ├── 2026-W42.md
    └── 2026-10.md
```

- 文件名可含中文；项目条目 id 是 vault 内相对路径去掉 `.md`（如 `项目/xinghu-intelligence`）；主题板 id 如 `行业/机器人/_主题`，细分赛道如 `行业/机器人/仓储机器人`，单条观点如 `行业/机器人/仓储机器人#仓储-001`。
- 项目条目格式（六小节、frontmatter 字段）与行业两级观点板格式（主题板、观点板、创建/拆并规则）见 [docs/FORMAT.md](docs/FORMAT.md)；完整虚拟范例见 [docs/EXAMPLE.md](docs/EXAMPLE.md)。
- 手改是安全的：插件每次扫描重新解析文件；项目条目不会重写它没改过的段落，未知 frontmatter 键和未知小节会保留。

侧边栏点 **投资记忆**，进入主栏页面。顶部显示标题、vault 路径和计数（项目 / 行业 / 到期 / 全部）。

| 区域 | 能做什么 |
| --- | --- |
| 列表与筛选 | 「全部 / 项目 / 行业 / 到期」四个页签；行业按「主题 → 细分赛道 → 观点」树展示；每行显示名称、类型、判断、行业/轮次、下次复盘，过期高亮 |
| 搜索 | 在已扫描条目里按名称、标签、摘要即时过滤 |
| 详情 | 字段网格 + 正文小节（Markdown 渲染） |
| 新建 / 编辑 | 项目表单：类型、名称、行业、轮次、判断、置信度、标签、一句话判断、判断依据、关键假设、风险、复盘周期 |
| 新建主题 / 细分赛道 | 手动创建；模型可提案，但需要你确认（明确说"记一下这个行业"时允许直接建一个主题 + 一个细分赛道） |
| 复盘 | 填结论、进展、偏差、更新判断、置信度、下次复盘日期，追加到复盘记录 |
| 本周简报 | 生成并保存当期的周报（`简报/` 下）：项目变化 + 按主题分组的行业观点变化 |

| 设置 | 「外观（全局）」：跟随系统 / 亮色 / 暗色；「知识库位置」：选择/输入绝对路径、保存或恢复默认 |
| 刷新 | 立即重新扫描 vault |
| 空库 | 显示 vault 路径和「写入示例记录」按钮，把 `samples/` 的示例写进空库 |

> 行业树与「新建主题 / 新建细分赛道 / 新建观点 / 修正 / 削弱 / 证伪 / 归档」操作已实现；旧格式行业条目在行业树底部只读展示，标注「待迁移」。

面板在窗口重新聚焦时和每 30 秒自动刷新一次；配色跟随 Harness 主题（浅色/深色）。

## 对话中使用

助手通过一个工具 **`vc_memory`** 访问记忆，用 `action` 选择操作。模型在需要时会自己调用，你也可以直接说需求。

| action | 作用 |
| --- | --- |
| `status` | vault 路径与可写性、配置、计数、到期数、同步方式与警告 |
| `list` | 列出条目（可按类型、到期筛选） |
| `search` | 按关键词搜索，返回命中片段（搜索词参数为 `query`） |
| `read` | 读取一篇的完整内容与各小节 |
| `upsert` | 新建或更新一篇（按名称/别名匹配已有条目） |
| `review` | 追加一条复盘并推进下次复盘时间 |
| `digest` | 生成周报/月报，保存到 `简报/` |
| `sync` | 查看 Git 状态、提交、推送；未启用 Git 时报告云盘同步状态 |
| `theme` | 行业主题：`op=create/list/read`；`create` 需要你明确要求并 `confirm:true` |
| `sector` | 细分赛道：`op=create/list/read`；创建时带范围句、首条观点 |
| `view` | 行业观点：`op=add/revise/weaken/falsify/archive`，修正时原地更新并记日志 |

其余参数与 HTTP 接口字段基本一一对应（`type` / `name` / `sector` / `stage` / `verdict` / `confidence` / `tags` / `aliases` / `summary` / `thesis` / `assumptions` / `risks` / `evidence` / `reviewCycleDays` …），细节见 [docs/API.md](docs/API.md)。

> 行业结构/观点动作已经实现：`theme` / `sector` / `view`；`upsert` 现在只用于项目条目，行业请用 `view` 操作。

可以直接这样说：

- 「记一下星弧智能：A 轮，看好，置信度 4，一句话判断是工业多模态质检里少有的能把交付做轻的团队。」
- 「我上次为什么给「边缘算力基础设施」打看好？关键假设验证到哪一步了？」
- 「这周哪些条目到期复盘？先更新星弧智能的复盘，再生成一份周报。」

## 三种触发方式

1. **手动**：面板按钮完成新建 / 编辑 / 复盘 / 简报 / 同步；或在对话里让助手调用 `vc_memory`（「查一下…」「记一下…」）。
2. **自动（系统提示词）**：`injectPrompt` 打开时，Harness 在系统提示词里保留一段「投资记忆」，包含条目计数、到期复盘、vault 路径和使用规则。模型因此在你没提「投资记忆」时也会主动回忆相关判断、提示你复盘。
3. **定期简报**：`autoDigest`（`off` / `daily` / `weekly` / `monthly`）+ `digestWeekday` + `digestHour`。`weekly` 在每周 `digestWeekday`（ISO 星期，1 = 周一 … 7 = 周日，默认 1）、`monthly` 在每月 `digestWeekday` 日（1–28）的 `digestHour` 点之后生成；插件每 5 分钟检查一次，所以实际写入在整点后的第一次检查。**定时器只在 Harness 进程运行时生效**——程序退出或电脑休眠期间不会写；如果整段周期机器都关着，错过的那期不会补写（简报按当期命名），需要时在面板点「本周简报」或让助手生成。

## 多设备同步

记忆文件夹本身就是同步单位；插件不做合并。两种常见做法：

### 方案 A：OneDrive（默认，最省事）

1. 保持 `vaultDir` 为空：vault 就在 `<OneDrive>\VC-Memory`，OneDrive 客户端已经替你同步。
2. 另一台机器登录同一 OneDrive 账号，同样保持默认（或把 `vaultDir` 指到该文件夹）。
3. 不需要 Git、不需要额外配置；面板「同步」会显示为云盘同步。
4. 冲突由 OneDrive 处理（可能留下冲突副本）；项目复盘记录是追加写入，日常几乎不会撞；行业观点是原地更新，冲突时取较新一侧并把旧结论写进日志。

### 方案 B：Git / GitHub（可选，默认不配置）

插件**默认不配置 Git**；只有你想用 Git 而不是（或同时用）OneDrive 时才需要显式打开。

先在 vault 目录建仓库：

```sh
cd "<vault 目录>"
git init
git add -A
git commit -m "init VC Memory"
git remote add origin git@github.com:<你>/vc-memory.git
git push -u origin main
```

另一台机器 `git clone` 到本地目录，并把 `vaultDir` 指向它。然后在 profile 补丁层显式打开 Git 同步（这是可选项，不配置就保持 OneDrive 文件夹同步）：

```yaml
- id: vc-memory
  name: '@local/vc-memory'
  config:
    vaultDir: 'C:/Users/<你>/VC-Memory'
    git:
      enabled: true
      autoCommit: true
      autoPush: true
      remote: origin
      branch: main
```

- `autoCommit`：每次写入（面板或工具）后自动提交。
- `autoPush`：提交后再推送到远端；`branch` 留空表示当前分支。
- 面板 **同步** 按钮 / `vc_memory` 的 `sync` 动作：查看状态、手动提交、推送。
- **多设备工作流**：编辑前先拉取（手动 `git pull`，或让 Git 客户端自动 fetch/pull）——插件不做 Git 合并；编辑后由「同步」按钮或 `autoPush` 推送。
- **冲突策略**：同一文件在两台机器同时修改时由 Git / OneDrive 判定，通常 last write wins；项目复盘记录是追加写入，冲突很少。行业观点板是原地更新，冲突时取较新的一侧、把旧结论补进 `日志.md`，手工合并后再提交；真遇到项目条目冲突时保留双方的复盘块、判断字段取较新的一侧。

## 配置修改

本插件不注册配置表单，配置统一写在 profile 的补丁层：`~/.dsh/profiles/<profile>/cordis.patch.yml`（本机为 `C:\Users\<你>\.dsh\profiles\desktop\cordis.patch.yml`）。注意：按 id 覆盖会整体替换该行的 `config`，但插件对缺失的键使用内置默认值，所以只写要覆盖的键即可：

```yaml
- id: vc-memory
  name: '@local/vc-memory'
  config:
    reviewCycleDays: 45
    autoDigest: daily
```

重启（或被热加载）后生效。bundle 自带默认值如下：

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `vaultDir` | `''`（自动） | vault 目录；空串按 OneDrive → Documents 顺序解析；也可在面板「设置」里覆盖 |
| `language` | `zh` | 界面文案语言偏好（库内容本身与语言无关） |
| `reviewCycleDays` | `30` | 新条目默认复盘周期（天） |
| `autoDigest` | `weekly` | `off` / `daily` / `weekly` / `monthly` |
| `digestWeekday` | `1` | `weekly`：ISO 星期（1 = 周一 … 7 = 周日）；`monthly`：当月日期 1–28 |
| `digestHour` | `9` | 生成简报的整点（0–23） |
| `injectPrompt` | `true` | 是否在系统提示词中注入「投资记忆」段落 |
| `git` | **未配置（默认不启用）** | 可选：Git/GitHub 同步；需要时在补丁层显式添加 `git:` 块 |
| `git.enabled` | `false` | 启用 Git 同步（仅在写了 `git:` 块时才需要） |

## 隐私与边界

- 记忆是**明文 Markdown**：没有数据库、没有隐藏状态、没有遥测，插件自身也不提供云服务。
- 文件是否离开本机，只取决于你选的同步方式（OneDrive / iCloud / Dropbox / Git 远端）；不启用云同步，它就只在本机。
- 系统提示词只放计数、到期提醒、vault 路径和使用规则，不注入正文；需要具体内容时模型才通过工具读取。你在对话里让模型读写的内容会作为对话上下文发给模型服务商——和任何对话一样。
- 敏感判断可以不启用云同步，只留在本地 vault。

## 常见问题

**打开面板显示 vault 不存在 / 列表是空的？**
先看面板顶部显示的实际 vault 路径。默认路径取决于 OneDrive 是否存在；自己设了 `vaultDir` 时确认目录存在且可写。也可以在面板「设置 → 知识库位置」里直接选择/输入路径并保存；首次打开会自动创建目录，空库用「写入示例记录」填充。

**同步提示 git 不可用？**
安装 Git（Windows 装 Git for Windows）并确保 `git` 在 PATH 里，然后重启 Harness；也可以在面板「同步」里查看具体输出。没有 Git 不影响使用，把 `git.enabled` 保持 `false`、用 OneDrive 同步即可。

**「到期」是怎么算的？**
`next_review ≤ 今天` 即到期，列表按过期天数高亮。复盘后 `next_review = 复盘日 + review_cycle_days`（复盘时也可以手填日期）；已有条目以自己的 `review_cycle_days` 为准，可在编辑里逐条调整。

**怎么改名或移动一篇？**
在面板「编辑」里改名称只更新显示名，不会移动文件；条目 id 是 vault 内相对路径，所以在磁盘上移动/改名 `.md` 后刷新，条目会按新路径重新出现。不要在两台设备上同时移动同一篇。

**怎么删除一篇？**
直接删掉对应的 `.md` 文件，刷新后列表里就没了——插件没有数据库，删除不留下隐藏残留。若开了 Git，历史提交里仍能找回。

**简报没有按时出现？**
定时器只在 Harness 运行时生效，整期错过不会补写。检查 `autoDigest` / `digestWeekday` / `digestHour`，或手动点「本周简报」生成一份。

**两台机器改冲突了怎么办？**
先 `git pull` 或等云盘同步，再在面板里看文件。项目复盘记录是追加的，建议两边都保留；行业观点板按「最后修正时间 + 当前结论」就地更新，冲突时取较新的一侧，把旧结论写进 `日志.md` 或手工合并后再同步。

**行业观点板和现在的行业条目有什么区别？什么时候可用？**
行业条目现在已经是两级观点板：`行业/<主题>/_主题.md`（主题板）+ `行业/<主题>/<细分赛道>.md`（观点板），多条观点以「时间戳 + 当前结论」呈现，状态为 有效/待验证/被削弱/已证伪，修正时原地更新、旧→新摘要进 `日志.md`。代码已实现；重启 Harness 后生效。旧的扁平行业条目仍会在行业树底部只读展示，标注「待迁移」。

**主题/细分赛道由谁创建？边界在哪？**
默认由你手动创建，或模型提案后你确认。唯一例外：你明确说"记一下这个行业/赛道"且没有对应板，模型可直接创建**一个主题 + 一个细分赛道**，但必须同时写范围句、初始观点，并在 `日志.md` 记录；不确定归到哪个主题时仍只提案。新建细分赛道要过五测试（同一批客户/竞品/成本结构、证据可复用、决策会不同、可证伪、能跨 ≥2 个项目复用）+ 范围句 + 3 家可比公司；只服务一个公司的判断放 `项目/`。拆分/合并也由模型提议、你确认。
